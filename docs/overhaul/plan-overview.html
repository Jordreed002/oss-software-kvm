01

The everyday experience

A widget when you need it

Open the tray or menu-bar icon to see connection state, the actual input destination and Pause/Resume. A compact surface around 360 logical pixels wide replaces the daily dashboard.

Focused windows for longer tasks

Setup covers permissions, verified pairing, display arrangement and an input test. Settings and troubleshooting open separately. Multiple monitors, keyboard mapping and optional plain-text clipboard remain in scope.

Close dismisses the window. Pause restores local input and pauses clipboard sharing. Quit stops sharing and both processes after confirmed cleanup. Launch at login is opt-in.

Light/dark themes, keyboard navigation, screen readers, high contrast, reduced motion and text scaling are part of the first implementation.

02

Rebuild the Rust application

Design fresh ownership, concurrency, module and protocol boundaries. Rebuild capture, routing, injection, session coordination, configuration and native lifecycle around explicit contracts. Existing crates are reference material, not an automatic starting structure.

Native shell + new frontend

Tray/menu bar, windows, presentation, settings drafts and update orchestration. Tauri and React are proposed, subject to the shell performance spike.

↔

New Rust background agent

Identity, pairing, committed configuration, topology and input authority. Available while sharing is off, with no active capture until enabled.

Reuse is selective: mapping tables, geometry, parsers, native bindings and credential adapters are candidates. Each reused part needs a recorded contract, safety review, tests and performance evidence.

Keep the legacy build for comparison, import and rollback. Only one capture engine may own a user desktop at a time. Production code implementation has not started.

Budgets come before architecture approval. Phase 0 sets numeric input-latency and resource targets on named machines. Matching an inadequate old baseline is insufficient. Warm widget opening has a proposed p95 target of 150 ms; this is a target, not a measured result.

04

The delivery sequence

0Baseline, architecture & visual direction

Measure the existing build, design new Rust contracts, start the reuse register, produce two visual variants and prototype the installed shell and native permissions on both platforms.

Gate: agreed platform matrix, ownership model and numeric performance/safety budgets before committing to the architecture.

1New Rust foundation & fast input path

Implement a minimal two-host authenticated capture-to-injection path, fresh state/session ownership and native adapters. Build emergency release alongside normal delivery.

Gate: both directions pass ordering and recovery tests and meet the initial latency/smoothness budgets.

2Background agent & local control

Add idle operation, identity, verified enrollment, topology, persistence and a versioned local API. Command acceptance, application and failure are distinct outcomes.

Gate: headless pairing and layout sync; one configuration writer; delayed commands and event gaps recover safely; control-plane load stays within input budgets.

3New tray shell, widget & setup

Build the compact everyday UI, native menus, supervision, onboarding and focused settings. Validate placement, focus, mixed DPI and assistive technology.

Gate: 100 open/dismiss cycles leave sharing unchanged; native Pause/Quit work through webview failure; visible and hidden resource targets pass.

4Security & migration acceptance

Review enrollment, harden local endpoint identity/authorization, integrate OS credential storage and import old settings and trust with interruption recovery. Release diagnostics use local IPC.

Gate: unauthorized clients rejected, no unauthenticated release LAN diagnostics, and interrupted migration preserves identity or requires explained verified re-pairing.

5Lifecycle, physical acceptance & soak

Test held input during pause/quit, peer loss, crashes, lock/sleep, user switching, display changes and permission revocation. Measure under load with the UI visible and hidden.

Gate: 100 combined lifecycle/fault transitions per receiving OS without stuck input or competing capture owners; a 24-hour two-host soak and the full performance matrix pass.

6Installed release & cutover

Package a compatible shell/agent pair, sign Windows artifacts, sign/notarize macOS, and validate startup, upgrade, uninstall and rollback. Start with signed manual releases.

Gate: clean install and paired upgrade/recovery pass on the approved hardware matrix. Stop legacy capture before enabling new capture. Add user-approved in-app updates after safe replacement and rollback are proven.

05

Safety, release & decisions

Safety remains independent of the UI

Emergency recovery, held-input tracking and destination-side cleanup survive renderer failure. Agent restart begins paused. Wake, unlock, permission recovery and safety faults require explicit Resume initially.

Ship on both platforms

Per-user Windows install and signed/notarized macOS app are proposed. Validate real permissions, startup, firewall behavior, updates and uninstall on installed builds. No telemetry upload is proposed.

Decide during phase 0: supported OS versions and CPU architectures; final app/helper identifiers; test-machine access; signing ownership and budget; numeric performance gates; legacy peer compatibility and migration policy.

Pinned desktop widget, multi-peer UI, WAN control, video/audio and privileged login-screen control are outside the initial scope. Calendar estimates follow the first measured end-to-end slice.
