# Replacement local API first contract

Implementation direction for the first serialized contract. This is a new protocol namespace, independent of legacy IPC and peer frames. The transport must authenticate endpoint/client identities; decoding JSON does not authorize commands.

Use a new `kvm-agent-api` crate with serde/serde_json and UUID serialization. Local JSON payloads are capped at 16 KiB before decoding. Numeric 64-bit request IDs and revisions travel as canonical decimal strings to prevent JavaScript precision loss. Reject noncanonical strings, overflow, JSON numeric representations, unknown fields, invalid UUIDs and nil instance IDs. Native owners supply cryptographically fresh instance IDs; the codec generates none.

Protocol name: `software-kvm-agent`, schema version 1. Messages are tagged snake_case enums. The first request is Hello with inclusive minimum/maximum schema versions. Negotiate only valid overlapping ranges; reject unsupported versions explicitly. Clients must also verify the chosen version against the range they offered. Mutations and snapshot requests include expected agent instance and correlation ID. Resume includes an expected snapshot revision. Pause, Failsafe and Quit have no revision precondition; stale observations must not prevent a safety stop. Snapshot revision is not a committed configuration revision. Future settings commands need a separate configuration revision. No topology/enrollment settings commands until their owning services exist.

Server replies separate Hello, Snapshot, CommandResult and protocol Error. Protocol errors use closed reasons for unsupported version, wrong protocol, malformed request, Hello required, instance mismatch and unsupported operation. Errors never echo client text. Include the correlation ID when a request was decoded; Hello and undecodable input have no correlation ID. A command outcome is Accepted, Applied with resulting revision, or Rejected with structured reason. A client timeout is unconfirmed and must not be converted to rejection or success. State includes instance, snapshot revision, user intent, lifecycle, separate safety latch, separate cleanup failure, input destination and readiness/capabilities. User intent is paused or sharing_requested; it does not establish input authority. Use typed supported/unsupported values rather than inferring capabilities from command names. Initially only read-only status is supported by a future idle-agent stub; no native capability is fabricated.

The server Hello must return its agent instance ID and bounded, character-restricted agent version. A client needs that ID before it can form the first instance-bound SnapshotRequest. Obtaining an expected instance from a filename, accepting a nil placeholder or guessing from a PID is not a valid bootstrap mechanism. Verify the native endpoint before Hello and bind all later requests to the returned instance. A snapshot with a different instance requires resynchronization. Build identity supplements native authentication; a version label alone does not prove code identity. These integration requirements must be checked when the draft codec is reviewed.

The initial snapshot may represent unknown input destination and unconfirmed prerequisites. Do not report confirmed local authority merely because the process is paused. Mutations must be matched to an authorized endpoint instance before dispatch; apply revision checks only where the request type requires them. Request deduplication and snapshot-event reconciliation belong to the owner, not this serialization crate. Every decoder, including a future TypeScript client, must reject duplicate JSON keys rather than accepting the last value.

Provide bounded encode/decode entry points for both directions and common JSON fixtures. Size checks must also cover encoding. Avoid retaining payload-bearing parse errors in diagnostics. Tests cover u64 maximum roundtrip, rejection of values above JavaScript's exact numeric range when represented as JSON numbers, version mismatch/reversed ranges, oversized payloads, unknown fields/variants, nil identity and exact serialized outcomes. These are software contract tests, not transport, authentication or native acceptance.
